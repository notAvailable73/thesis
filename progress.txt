NOTES / DECISIONS LOG
================================================================================

2026-04-21  Decision (Step 1): use softplus activation instead of ReLU for
            evidence computation. Reason: ReLU caused dead neurons (negative
            logit → zero evidence → zero gradient → unrecoverable). Logged
            in step1.txt sections 2-3.

2026-04-21  Decision (Step 1): KL anneal 0 → 0.5 over 200 steps. Reason: on
            25-sample support sets a fixed kl_weight=0.5 overwhelms the MSE
            signal and the model gets stuck at uniform predictions; ramp
            gives MSE time to grow evidence before the prior kicks in.

2026-05-13  Decision (Step 2): YAML configs with `extends:` over a Python
            dataclass. Reason: the MVT grid will need ~120+ small configs;
            each must be diff-readable and runnable from the CLI without
            editing source.

2026-05-16  Step 3 ran wandb in OFFLINE mode (not online). Reason: embedded
            API key was 36 characters; wandb requires 40+. The `wandb/`
            directory is sync-ready. Resolve before Step 10 starts (the
            MVT grid wants online tracking for cross-run comparison).

2026-05-19  Decision (plan.txt, Step 4): episodic meta-training, NOT
            per-episode-from-scratch. Reason: supervisor_briefing §6
            commits to "train on many episodes per epoch, validate on
            others, stop when validation plateaus" — that is meta-training.

2026-05-19  Decision (plan.txt, Step 4): 5-shot training only for Phase 2;
            1-shot deferred to the MVT grid (Step 10). Reason: Phase 2's
            §4.5 spec calls for a single Phase A baseline (two configs:
            evidential + softmax), not a grid.

2026-05-19  Decision (implementation.txt, Step 4): prototype-head meta-
            training instead of the proposal's linear head. Reason:
            classifier head trained over 64 train classes cannot
            transfer to 20 test classes; prototype similarity is the
            standard CIFAR-FS protocol. Documented as a methodology
            deviation in Chapter 3 of the thesis.

2026-05-19  Audit gap fix: Macro-F1, Full Fine-Tuning baseline, and Linear
            Probing baseline added to plan.txt and implementation.txt.
            They were missing from the original post-defence spec but
            are mandatory per proposal §6 and §7.

2026-07-08  Decision (Step 5, LoRA): target the 1x1 downsample conv of the
            final stage (layer4.0.downsample.0) — a pure channel matrix, so
            LoRA on it is the clean rank*(in+out) reparameterization, 12,288
            params @ rank 16 (inside the 9-15K band, comparable to Bottleneck).
            A 3x3 conv2 target would explode to >160K params (down-projection
            carries the full k*k kernel). Target set is a config knob
            (cfg.adapter.lora_targets) so it can be widened later.

2026-07-08  Flag (Step 5): implementation.txt 5.1's LoRA param formula
            "2*rank*(in+out)" is wrong by 2x; the honest A/B count is
            rank*(in+out). Tests assert the correct value; noted in step5.txt.

2026-07-08  Decision (Step 5, BatchNorm): for ALL backbone-trainable adapters
            (LoRA/BitFit/Full-FT) the trainer keeps the backbone in eval() mode,
            so BN running stats stay frozen at ImageNet values; only affine/conv
            weights update. Updating BN stats from 25-image supports is unstable
            and leaks query stats. Documented deviation from vanilla Full-FT.

2026-07-08  Decision (Step 5, Full-FT): its config sets collapse_threshold=0.0,
            which disables the R-EPISODIC-COLLAPSE guard (now gated on
            threshold>0), so the EXPECTED overfit/collapse completes and writes
            honest metrics instead of aborting the Colab run. LR 1e-5, wd 1e-4.

2026-07-08  Architecture (Step 5): LoRA/BitFit/Full-FT put trainable params
            INSIDE the frozen backbone. build_adapter now receives the backbone
            and mutates it in place; the model exposes backbone_trainable so
            adapter_features runs the backbone WITH autograd (vs no_grad for the
            frozen Bottleneck/Linear-Probe/legacy paths). The single_episode +
            Bottleneck paths stay byte-identical. Linear-Probe+softmax has 0
            trainable params -> train.py short-circuits to a train-free
            checkpoint (Adam rejects an empty parameter list).
