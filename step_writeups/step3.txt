1.  EXECUTIVE SUMMARY
================================================================================

Step 3 was a reproducibility step, not a methodology step. The same model
(frozen ResNet-18 + bottleneck adapter + linear head), the same loss
(Sensoy 2018 evidential MSE + KL with softplus activation, annealed
0 -> 0.5 over 200 steps), and the same data (CIFAR-100 test classes as
the CIFAR-FS stand-in, SVHN OOD) as Step 2. What changed is the surface
around those things:

  - A WandbRun wrapper in src/utils/wandb_utils.py is now the single
    logging surface. scripts/train.py logs per-step (loss,
    support_accuracy, lr, kl_weight); scripts/evaluate.py logs
    per-episode (accuracy, ECE, Brier, OOD AUROC) and uploads
    reliability / OOD histogram / confusion-matrix PNGs and the final
    JSON as artifacts. Online, offline, and disabled modes are
    first-class so the same code runs on Colab with an API key, on
    Colab without one, and under pytest.

  - src/utils/seed.py is now called at the top of every script.
    Determinism is on by default: cudnn.deterministic = True,
    cudnn.benchmark = False, CUBLAS_WORKSPACE_CONFIG set,
    torch.use_deterministic_algorithms(True, warn_only=True). All four
    seeds (Python random, numpy, torch CPU, torch CUDA) are tied to
    one integer from the YAML config.

  - configs/test_episodes.yaml is now the *only* source of truth for
    which 600 test episodes any evaluator uses. scripts/evaluate.py
    reads the seed list from this file; --num-episodes only controls
    how many of those seeds to consume (clipped at len(seeds)).

  - The Step 2 winner (evidential softplus_kl0.5) and the softmax
    baseline were re-trained and re-evaluated end-to-end through the
    new CLI on all 600 episodes. Both completed successfully on a
    Colab T4 in well under the spec's "30 minutes" budget. The
    evidential eval was then re-run a second time with
    --wandb-mode=disabled; filecmp.cmp confirms the two metrics.json
    files are byte-identical.

The R1 calibration story from Steps 1 and 2 survives the move to 600
episodes intact:

  evidential: acc 0.849 +/- 0.006   ECE_mean 0.162   AUROC 0.951
  softmax:    acc 0.823 +/- 0.006   ECE_mean 0.136   AUROC 0.850
  OOD AUROC gap: +0.101  (evidential)

All four spec exit criteria are met. Step 3 is closed.

2.  WHAT CHANGED RELATIVE TO STEP 2 (CODE-LEVEL)
================================================================================

Step 2 left three deliberate hooks for Step 3 to fill (see step2.txt,
section 7). Step 3 filled all three without touching the model, loss,
or trainer math.

----- New file: src/utils/wandb_utils.py ---------------------------------------

A 115-line module whose only export is the WandbRun class plus a
make_run_name helper. Three design choices recorded for audit:

  1. Every wandb import lives inside this file. The rest of the
     codebase (trainer, evaluator, scripts) holds a WandbRun handle and
     calls .log() / .log_image() / .log_artifact() / .finish(). If we
     swap wandb for a different logger later, only this file changes.

  2. disabled=True is honoured even when wandb is installed. This
     matters under pytest (don't fork a wandb process for every test)
     and under the reproducibility re-run in section 6 (where the
     second run must not register a duplicate on the dashboard).

  3. Run-name format follows the spec exactly:
     "{backbone}_{adapter}_{head}_{dataset}_{kshot}shot_seed{seed}",
     so dashboard filtering by name segment works without surprises.

----- New file: src/utils/seed.py ----------------------------------------------

set_seed(seed, deterministic=True) seeds python.random, numpy,
torch CPU, and torch CUDA, then -- when deterministic is True -- flips
cudnn.deterministic, cudnn.benchmark, sets CUBLAS_WORKSPACE_CONFIG
(needed for deterministic CUDA matmul since CUDA 10.2),
PYTHONHASHSEED, and calls torch.use_deterministic_algorithms(True,
warn_only=True). The warn_only flag is deliberate: it lets older
non-deterministic kernels degrade to a printed warning rather than
crash the run.

----- New file: src/utils/plots.py ---------------------------------------------

Three plot functions -- reliability_diagram, ood_histogram,
confusion_matrix -- previously inlined inside
notebooks/step1_calibration_fix.ipynb. Lifting them into src/ means
scripts/evaluate.py emits the same plots without re-running Step 1's
notebook. All three use matplotlib.use("Agg") so they work under
subprocess on Colab and CI.

----- Modified: src/trainers/fewshot_trainer.py --------------------------------

Accepts an optional wandb_run: WandbRun argument. When present, the
trainer logs per-step {loss, support_accuracy, lr, kl_weight} via
wandb_run.log(). When absent (or disabled), the same code path emits a
stdout line as before. The KL anneal logic from Step 2 is unchanged:
linear ramp from 0 to kl_weight_max over kl_anneal_steps, holding flat
afterwards.

----- Modified: scripts/train.py and scripts/evaluate.py -----------------------

Both scripts now accept --wandb-mode {online,offline,disabled}, default
"online". scripts/evaluate.py additionally accepts --results-suffix
(used in Step 3 with value "step3" to write
results/step3_bottleneck_<head>_metrics.json rather than overwriting
the Step 2 files) and --num-episodes (clipped to the length of the
seed list from configs/test_episodes.yaml).

Both scripts call src/utils/seed.set_seed(cfg.seed) before any model
or data construction, so determinism is on by default for every CLI
invocation.

----- New file: configs/test_episodes.yaml -------------------------------------

A YAML with num_episodes: 600 and seeds: [0, 1, 2, ..., 599]. The
comment block at the top of the file says "Do not regenerate. Treat as
committed truth." -- because the entire point is that Step 5's 48-run
MVT grid uses the same 600 episodes per cell, so paired-difference
statistics work.

scripts/evaluate.py reads the seed list from this file. The base
config's old eval.num_episodes: 20 is gone; in its place,
eval.episodes_file: configs/test_episodes.yaml.

3.  HOW STEP 3 IMPROVED ON STEP 2
================================================================================

Step 2 fixed the layout; Step 3 fixed the run record. Concretely:

----- Improvement 1: every run leaves a permanent trace ------------------------

In Step 2 the only artefacts a run produced were the local metrics
JSON and the local PNGs. In Step 3 every run additionally produces a
wandb run (or in offline mode, a wandb/ directory that can be synced
later) with full per-step training curves, per-episode evaluation
curves, all four PNGs, the metrics JSON as an artifact, and the
resolved config as a structured object. The run name and tags make
filtering for "step3 evidential" or "step3 eval" a one-line UI
operation.

----- Improvement 2: same config -> byte-identical metrics.json ----------------

Step 2 reported reproduction "within tolerance". Step 3 reports
reproduction at the byte level. The notebook (section 6) copies the
first evaluation's JSON aside, re-runs evaluate with --wandb-mode
disabled, then asserts filecmp.cmp(first, second, shallow=False).
This holds because:

  - set_seed pins all four RNGs to cfg.seed (42 in both configs);
  - cudnn.deterministic + CUBLAS_WORKSPACE_CONFIG remove the two
    main sources of CUDA non-determinism (algorithm selection and
    matmul workspace allocation);
  - the seed list is read from configs/test_episodes.yaml, not
    generated at runtime, so the iteration order of episodes is
    fixed;
  - the JSON serialiser uses sort_keys=True and indent=2 so even
    dict ordering is stable.

The Step 3 exit criterion "running the same config twice gives
byte-identical metrics.json" passed without manual intervention.

----- Improvement 3: tight CIs replace point estimates ------------------------

Step 2 reported single-number metrics over 20 episodes -- enough to
verify the refactor preserved behaviour, not enough to defend a
thesis claim. Step 3 reports mean and 95% CI over 600 episodes:

  evidential accuracy: 0.849 +/- 0.006 (95% CI), std 0.069
  softmax    accuracy: 0.823 +/- 0.006 (95% CI), std 0.069

The accuracy gap (+0.026 in favour of evidential) is now wider than
either CI half-width (0.006). Same for AUROC: +0.101 gap against
evidential std 0.035 and softmax std 0.055. These are real
differences, not seed noise.

----- Improvement 4: tests still pass, no regression --------------------------

pytest tests/ returned 28 passed in 12.67s after the Step 3 edits.
The Step 2 smoke tests are unchanged -- new functionality landed in
new files and through optional kwargs on existing entry points, not
by editing the modules the tests cover. If any of those 28 tests had
failed, Step 3 would not have closed.

----- What Step 3 did NOT do ---------------------------------------------------

  - No new science. Sensoy 2018 evidential MSE + KL, softplus
    activation, KL annealed 0 -> 0.5 over 200 steps. Same as Step 2.
  - No proper CIFAR-FS split. Still the 5 classes from CIFAR-100 test
    used as a stand-in. Step 4 introduces the Bertinetto 64/16/20
    split.
  - No episodic training loop. Still one 25-image support set per
    run, 200 inner-loop steps. Step 4 introduces per-epoch episode
    sampling.
  - No grid. Just two configs (evidential winner, softmax baseline).
    The 48-run MVT grid is Step 5.

================================================================================

Step 3 deliberately stops short of touching the data pipeline so that
Step 4 has clean insertion points:

  - configs/test_episodes.yaml is the canonical 600-seed list. Step

    Step 4 numbers are paired episode-for-episode on the *new* test
    classes.

    step=epoch). Step 4's episodic trainer just opens one WandbRun
    for the full training loop and logs query_accuracy / ECE /
    Brier per epoch on the validation split. No new logging surface
    needed.

  - src/utils/seed.set_seed already pins everything Step 4 needs;
    the episodic sampler in src/datasets/episode_sampler.py just has
    to thread a per-episode seed through to torch.Generator. The
    set_seed call at the script top-level still controls the outer
    randomness (split shuffle, optimiser init, etc.).

  - scripts/evaluate.py's --num-episodes flag will continue to work
    after Step 4 replaces the dataset, because the seed list lives
    in a separate file and the evaluator only depends on
    cfg.dataset.name to pick which class set to sample from.

None of this leaks back into Step 3's code paths. Step 3 is a closed
unit.
