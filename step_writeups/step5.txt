0.  PAPER-GROUNDED REASONING (per thesis_implementation_instructions §5)
================================================================================
Sources: PAPER SUMMARIES/PEFT_summaries.txt — LoRA (Hu 2021, paper 2), BitFit
(Ben-Zaken 2022, paper 3), ConvLoRA (Aleem 2024, paper 5) and Conv-LoRA
(Zhong 2024, paper 6) for LoRA-inside-CNN-convs, Conv-Adapter (Chen 2022,
paper 4) for the 1x1-vs-locality caveat, Unified View (He 2022, paper 7) for
insertion-form/scaling vocabulary.

LoRA
  WHAT: W_eff = W_frozen + (alpha/rank) * B @ A, A Kaiming-uniform, B=0 so the
  update is identity at init (Hu 2021). Applied here to the backbone's OWN conv
  weights, not the pooled feature (that was the mis-named Step 2 stub).
  PROS: exactly the proposal's "LoRA reparameterizes weight matrices" and the
  named "Standard LoRA + Softmax" baseline; zero inference overhead once merged;
  ConvLoRA/Conv-LoRA prove it works inside CNN convs in extreme low-data (10
  images) regimes — a close match to our 25-image support sets.
  CONS/FIT: on a 3x3 conv the down-projection carries the full k*k kernel and
  the param count explodes (>160K at rank 16 for a 512->512 conv2), breaking
  comparability with Bottleneck. RESOLUTION: target the 1x1 downsample conv of
  the final stage (layer4.0.downsample.0). A 1x1 conv is a pure channel matrix,
  so LoRA on it is the clean rank*(in+out) matrix reparameterization — and it
  avoids the "loss of locality" failure Conv-Adapter (Chen 2022) attributes to
  1x1 FEATURE adapters (we adapt a weight, and retain the frozen 1x1 conv, so
  the parallel 3x3 path's locality is untouched). At rank 16, 256->512:
  16*(256+512) = 12,288 trainable params — inside the exit-criteria 9-15K band.
  DEVIATION FLAGGED: implementation.txt 5.1 states the analytical count as
  "2 * rank * (in + out)". The honest count for a standard A/B decomposition is
  rank*(in+out) — exactly HALF. tests/test_lora.py asserts the correct value.
  Target set is configurable via cfg.adapter.lora_targets, so widening it later
  (e.g. also conv2 of each layer4 block) is a one-line config change.

BitFit
  WHAT: freeze all weights and gains; train only additive bias vectors
  (Ben-Zaken 2022). For torchvision ResNet-18 the convs are bias-free (BN
  follows), so the only biases are the BatchNorm shifts (beta). We unfreeze
  exactly the `.bias` params — NOT the BN gains (gamma) — staying true to
  "bias-only" rather than "affine-only". ~4,800 params (all BN betas).
  FIT: the proposal's extreme "<0.1% params" selective baseline for RQ2. Note
  Ben-Zaken report bias-only tolerates/needs a LARGER LR than full-FT; we keep
  the Phase-2 LR (5e-3) for comparability with Bottleneck/LoRA and note this.

Full Fine-Tuning (proposal §6 baseline)
  WHAT: unfreeze the whole backbone (~11.18M params, fc removed). EXPECTED to
  overfit catastrophically on 25-image support sets — the collapse IS the
  result (proposal §3 Problem 1: parameter inefficiency). LR lowered to 1e-5 +
  weight_decay 1e-4 to give it a fair chance; the R-EPISODIC-COLLAPSE guard is
  DISABLED (collapse_threshold: 0.0) so the pathological run completes and
  writes honest numbers instead of aborting.

Linear Probing (proposal §6 baseline)
  WHAT: backbone frozen, no adapter, only the head trains. Under the param-free
  prototype head: softmax => 0 trainable params (training-free nearest-
  prototype); evidential => 2 trainable params (the head's learnable evidence
  affine). The most extreme PEFT point on the curve — all transfer from frozen
  ImageNet features.

CARRIED-IN ASSUMPTION (untested): the evidential evidence-affine (scale 2,
bias -6) was VAL-selected on BOTTLENECK features in Step 4.5. We reuse it for
every adapter (cosine logits are bounded, so it should transfer), but the
per-adapter CALIBRATION numbers should be sanity-checked on VAL before being
trusted. A per-adapter VAL sweep is out of Step 5 scope (Step 10's grid).

DOCUMENTED DEVIATION (BatchNorm): for every backbone-trainable adapter
(LoRA/BitFit/Full-FT) the episodic trainer keeps the backbone in eval() mode,
so BN RUNNING STATISTICS stay frozen at their ImageNet values; only the affine
(BitFit beta; Full-FT gamma+beta) and conv weights (LoRA A/B; Full-FT) update.
Updating BN stats from 25-image support batches is unstable and would leak
query statistics — freezing them is standard few-shot practice.


================================================================================
1.  WHAT WAS BUILT
================================================================================
Adapters (src/adapters/):
  lora.py        REWRITTEN. LoRALayer (linear reference form), LoRAConv2d
                 (wraps a frozen conv, adds low-rank update, identity at init),
                 LoRAAdapter (injects LoRAConv2d into cfg.adapter.lora_targets
                 inside the backbone; its own forward is identity on the pooled
                 feature — the adaptation lives in the backbone).
  bitfit.py      NEW. Unfreezes only backbone `.bias` params (BN betas).
  full_ft.py     NEW. Unfreezes the entire backbone.
  linear_probe.py NEW. No-op; backbone stays frozen.
  __init__.py    build_adapter(spec, dim, backbone=None) extended to
                 {bottleneck, lora, bitfit, full_ft, linear_probe}. In-backbone
                 adapters require `backbone`; each adapter advertises a
                 `backbone_trainable` class flag.

Model (src/models/bpeft_model.py):
  build_model now passes the backbone to build_adapter and stores
  model.backbone_trainable. BPEFTModel.adapter_features runs the backbone WITH
  autograd when backbone_trainable, else under no_grad (legacy Step 1-4 path,
  byte-identical for Bottleneck / single_episode).

Trainer (src/trainers/episodic_trainer.py):
  + freeze_backbone flag: only re-freezes backbone params each epoch for
    post-pool / linear-probe adapters; LoRA/BitFit/Full-FT keep their
    in-backbone params trainable. BN is kept in eval() for ALL types.
  + collapse guard gated on collapse_threshold > 0 (Full-FT sets it to 0.0).
  + _adapter_grad_norm generalized to ALL trainable params (LoRA/BitFit/Full-FT
    keep params in the backbone, where model.adapter is empty). Identical to
    the old adapter-only sum for the frozen-backbone Bottleneck path.

Scripts (scripts/train.py):
  + passes freeze_backbone = not model.backbone_trainable to the trainer.
  + zero-trainable-parameter path: Linear-Probe + softmax has no params to
    optimise (Adam rejects an empty list) — _save_trainfree_checkpoint runs one
    val pass for a reportable accuracy and saves an episodic-schema checkpoint,
    skipping meta-training. scripts/evaluate.py loads it unchanged.

Configs (8): configs/exp_phase3_{lora,bitfit,full_ft,linear_probe}_{evidential,
  softmax}.yaml. Evidential configs extend exp_phase2_evidential_retuned.yaml
  (the VAL-selected R-EDL config — instructions.txt §3); softmax configs extend
  exp_phase2_softmax.yaml. Full-FT overrides train.lr=1e-5, weight_decay=1e-4,
  trainer.collapse_threshold=0.0.

Tests (4 new + test_adapters.py updated): test_lora.py, test_bitfit.py,
  test_full_ft.py, test_linear_probe.py. The old pooled-feature LoRA-stub tests
  were removed (the stub no longer exists).

Runner: scripts/run_step5.sh loops the 8 train+eval pairs (resumes by skipping
  existing metrics JSONs).

4.3  proposal §6 BASELINES (Full Fine-Tuning + Linear Probing)

  Full-FT  (11.18M params) — acc 0.888 evid / 0.905 softmax
    The proposal predicted catastrophic overfit -> accuracy BELOW every PEFT
    method. THAT DID NOT HAPPEN: Full-FT softmax (0.905) is the HIGHEST-accuracy
    run of the whole study, ~2-3 pp above the PEFT pack. This is NOT the data
    leak the risk note warned about — it is a PROTOCOL mismatch:
      - "Overfits on 25 images" assumes PER-EPISODE fine-tuning (the Step 1-3
        single_episode path). The Phase-2 EPISODIC protocol META-TRAINS one
        shared backbone across ~600 episodes/epoch (thousands of distinct train
        images), then FREEZES it at test and classifies by prototype similarity
        — no per-episode adaptation. Full-FT never fits 25 images; it fits the
        64-class train distribution, which simply yields better CIFAR features.
      - No leak path: train (64) and test (20) classes are DISJOINT; BN running
        stats are frozen; best_val_epoch=6 (it trained and early-stopped, did
        not memorise); LR 1e-5 moves the 11M weights only gently from ImageNet.
    HONEST REFRAME of proposal §6: under episodic meta-training, Full-FT is NOT
    a failure mode — it is the expected TOP of a PARAMETER<->ACCURACY curve. The
    thesis point becomes EFFICIENCY, not viability: PEFT reaches ~98% of Full-FT
    accuracy (Bottleneck 0.884 / BitFit 0.881 vs 0.905) while training 660x-
    2330x FEWER parameters (16.9K / 4.8K vs 11.18M; 0.04-0.15%), and
    Linear-Probe matches it at 0 params. Replace "Full-FT overfits so PEFT is
    necessary" with "PEFT gets ~98% of Full-FT accuracy at <0.2% of the
    trainable parameters."

  Linear-Probe  (0 / 2 params) — acc 0.874 (both heads)
    As predicted, a strong frozen-feature baseline: it MATCHES Bottleneck /
    BitFit accuracy with 0 (softmax) or 2 (evidential) trainable params —
    confirming "few-shot on good ImageNet features is hard to beat". BUT its
    calibration and evidential-OOD collapse (ECE 0.448 sm / 0.623 ev; vacuity
    0.708 / 0.584 on svhn / cifar100). Takeaway: frozen features buy ACCURACY
    for free, but a TRAINED adapter is needed for the evidential head's
    uncertainty to be well-shaped — which cleanly motivates the PEFT methods.

  Accuracy ranking (all 10 runs):
    Full-FT(sm) 0.905 > Full-FT(ev) 0.888 > Bottleneck(ev) 0.884 >
    BitFit(sm) 0.881 > Bottleneck(sm) 0.875 > Linear-Probe 0.874 >
    BitFit(ev) 0.869 > LoRA(sm) 0.860 > LoRA(ev) 0.828.

5.  HONEST CAVEATS
================================================================================
  - LoRA target set is a single 1x1 conv (12,288 params). It is a faithful
    LoRA, but a deliberately small-capacity one; if LoRA underperforms it may
    be capacity, not the method — widening lora_targets is a config change.
    CONFIRMED at run time: LoRA is the lowest-accuracy method (0.828 evid /
    0.860 softmax), consistent with the single-1x1-conv capacity ceiling.
  - The "2*rank*(in+out)" figure in implementation.txt is wrong by 2x; we use
    the honest rank*(in+out).
  - Evidence-affine reused from a bottleneck VAL sweep (see §0); per-adapter
    calibration not independently VAL-tuned in Step 5.
  - BN running stats frozen for all backbone-trainable adapters (see §0) — a
    documented deviation from vanilla Full-FT, justified for few-shot.
