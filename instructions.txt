--------------------------------------------------------------------------------
2.1  IMPORTANT: the current src/adapters/lora.py is NOT what you need — REWRITE it
--------------------------------------------------------------------------------
What exists today: `LoRAAdapter` in src/adapters/lora.py applies a low-rank
residual to the POOLED FEATURE VECTOR after the frozen backbone (dim -> rank
-> dim, added back). This is really a low-rank bottleneck adapter, not LoRA in
the sense the proposal means.

What Step 5 actually wants (implementation.txt 5.1): LoRA reparameterizes the
backbone's OWN weight matrices in place — `W_eff = W_frozen + (alpha/rank) *
A @ B` — applied to specific nn.Linear / nn.Conv2d layers INSIDE the frozen
ResNet-18 (e.g. the 1x1 convs in the last block). This changes what the
backbone computes, not what happens after it. You will need:
  - LoRALayer(in_features, out_features, rank, alpha, dropout=0.0)
  - LoRAAdapter that wraps a frozen backbone's target layers in LoRALayer
  - cfg.adapter.lora_targets in YAML to pick which layers get LoRA'd
  - Register it in src/adapters/__init__.py's build_adapter() factory
    (currently only knows "bottleneck" and "lora"-the-old-stub — same registry
    key, but the class it builds must change)

Existing test tests/test_adapters.py checks identity-at-init on the OLD stub —
you'll need to update/replace it (implementation.txt 5.9 wants
tests/test_lora.py: identity at init + analytical param count
2*rank*(in+out)).

4.  GOTCHAS THAT COST US REAL TIME — READ BEFORE YOU HIT THEM
================================================================================
  a) data/ is gitignored. After cloning, run:
       python scripts/build_cifar_fs_split.py
     before anything else. It fetches the canonical 64/16/20 Bertinetto split
     and writes data/cifar_fs_split.json. Do NOT hand-edit that file.

  b) If you run on Google Colab + Drive: DO NOT extract or scan large
     many-file archives (like TinyImageNet's ~120k files) into your Drive
     folder — Drive's FUSE mount does a network round-trip PER FILE and this
     will hang for HOURS (it did, to us). See src/datasets/tinyimagenet_ood.py
     for the pattern that avoids this: cache the single zip, copy it once to
     local disk (/content), read only what you need straight out of the zip,
     never extract. Apply the same rule to any new heavy dataset you add.

  c) If you build a Colab notebook: make it SELF-CONTAINED. Editing files on
     your own machine does NOT reach a Drive-mounted Colab session. Pattern to
     copy: notebooks/step4_5_settle.ipynb's "1b. Materialize" section, which
     `%%writefile`s every source file into the Drive repo at the top of the
     notebook before anything imports it. Don't assume `git pull` or manual
     file copying will happen reliably — bake the code into the notebook.

  d) Any hyperparameter search MUST select on the VAL split
     (configs/val_episodes.yaml, seeds 10000-10099) — NEVER on the 600 TEST
     seeds (configs/test_episodes.yaml, seeds 0-599). This is enforced by
     convention, not code, so it's on you to respect it. See
     scripts/step45_val_sweep.py for the pattern (in-process, not subprocess —
     subprocess output can silently vanish in Colab, which cost us a wasted
     run before we caught it).

  e) Reproducibility invariant: running the SAME config twice must produce a
     byte-identical metrics.json (sort_keys=True dump + fixed seeds). If a
     rerun differs, something is non-deterministic — fix it before trusting
     any result from that config.

  f) Never commit to git yourself unless explicitly asked — this project's
     convention is that a human reviews and commits. If you're an AI agent
     reading this: only read from git, never write.
